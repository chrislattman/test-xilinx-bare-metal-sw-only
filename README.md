# Bare-metal Xilinx application

![](blinking.gif)

This project is an example of a bare-metal software/hardware application for the Zynq-7000 SoC (specifically the Arty Z7-20 board).
The software application was developed in Vitis Unified IDE 2025.2, and it's built on top of an XSA file generated by Vivado 2025.2.

- The XSA file is generated in Vivado (by generating the block design and then running synthesis and then implementation/place & route)
- While there is no custom Verilog, the XSA file is still needed as it defines the hardware platform which the software runs on, including enabling the AXI GPIO used to toggle the LED in this example

## QEMU

The applications can also run in upstream QEMU's `xilinx-zynq-a9` machine (see `Makefile` for details). `make qemu` runs `hello_world` (A9#0) and `hello_world_1` (A9#1) together, and `make qemu_debug` does the same but halts and waits for GDB on `localhost:1234` (use the "QEMU A9#0 + A9#1 Debug" configuration in `.vscode/launch.json`). UART0 output is on `telnet localhost 5678`. The PL (AXI GPIO) and the system watchdog aren't emulated, and timing is approximate.

## Debugging

For more information on GDB debugging multiple standalone applications in a single processing unit, refer to https://docs.amd.com/r/2023.1-English/ug1400-vitis-embedded/Debugging-on-the-Command-Line

For .vscode/launch.json:

- Line 8 is mostly irrelevant when using customLaunchSetupCommands
- Lines 20-23 can be run in the VSCode Debug Console, where each command is prefixed with "-exec"

For CLion debugging:

- Make sure to run 'core1' in GDB terminal once application is loaded
